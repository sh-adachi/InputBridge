# InputBridge 1.0 動作確認

2026-11-03、Mac mini M4 / macOS 26.6.2 / ZOWIE XL2546K / Dell S2725QCで確認しました。

| 項目 | 結果 |
| --- | --- |
| アプリのビルド・アドホック署名 | 成功。`codesign --verify --deep --strict`で検証 |
| インストール | `/Applications/InputBridge.app`（1.0.2）。旧コピーも同じ版へ更新 |
| Dockからの起動 | 1.0.1で通常のDockアプリへ変更。手動起動時に設定を表示し、別コピーからの起動は稼働中のアプリへ開く要求を転送。冷起動、Finderからの再表示、設定を閉じた後の常駐を確認 |
| 設定画面の表示 | 実機UIで一般・自動切替・ショートカットを確認。ダークモード表示も確認 |
| 手動でZOWIEのみへ切替 | 成功。Dellのみがonline一覧から消え、ZOWIEはメイン・240 Hzを維持 |
| 非表示状態の維持 | 成功。アプリ稼働中は保持し、heartbeatが更新されることを確認 |
| デュアルへ復帰 | 成功。Dellは左側・120 Hz、ZOWIEはメイン・240 Hz |
| ショートカット | アプリ前面で⌃⌥⌘1による切替を確認。Carbonへのグローバル登録成功。別アプリ前面での物理キー操作は未確認 |
| 終了 | ⌘Qによる終了を確認。非表示中は先に保存構成へ戻す実装 |
| アプリの強制終了 | 非表示中に対象アプリをSIGKILLし、独立監視でデュアルへ戻ることを確認 |
| USB-Cのアプリ内登録 | 成功。非表示中の通信と復元を確認し、`0x1B1B`を登録 |
| DDC一時空応答 | 実機で検出。3回連続の正常応答を確認する方式へ修正し、再登録成功 |
| HDMI未登録の保護 | HDMI未登録の間は自動切替トグルが無効であることを実機UIで確認 |
| ログイン時起動 | SMAppServiceで実装。初期状態オフ。実ログイン動作は未確認 |
| スリープ復帰 | 復帰処理と新しい入力値による再判定を実装。実スリープ往復は未確認 |
| HDMIのアプリ内登録 | Switch表示中に`0x1B11`を取得。Dell無効化中の通信、復元、ZOWIE 240 Hz維持を確認して登録成功 |
| HDMI表示に合わせた自動切替 | 自動監視をオンにし、アプリ自身の判定でMacがZOWIE 1台・240 Hzへ移行したことを確認 |
| Switch電源オフからの自動復帰 | 無効化方式ではHDMI選択のまま省電力になり失敗。ミラーリング方式へ変更すると、Switchオン→オフでUSB-Cを検出し元のデュアル配置へ自動復帰。ユーザーもMac映像を確認 |
| ミラーリング方式 | USB-CとHDMI双方でDDC・複製・元の配置への復帰を検証。ZOWIE 240 Hz、Dell 120 Hzを維持。常用方法に設定 |
| 自動テスト | 19件。誤対象、DDC不正応答、連続一致、連続失敗、長いタイムアウト、切替間隔、再校正失敗、実測入力値、復旧監視など |

強制終了試験は`Reports/app-crash-recovery.json`、最初の手動非表示状態は`Reports/app-single-inventory.json`に保存しています。
アプリ内登録の生データは`~/Library/Application Support/InputBridge/observations.jsonl`と`experiments.jsonl`にあります。

実装済みの機能と、実機で未確認の条件を区別しています。このMacでは両入力を登録済みで、自動切替をオンにしています。
`Reports/switch-automatic-single.json`にSwitch使用中の自動シングル化の確認結果を保存しています。
